# 定时任务自动手机提醒

2026-09-10：用户已在同一 Wi-Fi 下验证真实手机配对、继续同一会话、手动锁屏通知，以及开启任务提醒后接收自动通知。点击任务通知未切到“任务消息”的问题修复后，用户加载新版并通过另一条受控任务通知确认能够直接定位。该结论限于这台测试手机与当前网络，尚未覆盖国内外 Android、跨网连接或正式服务调度。

## 开启与关闭

在主屏幕 PWA 的“连接”页面，先授权通知，再开启“接收任务提醒”。已有测试通知订阅默认不启用任务提醒。电脑设置中的设备卡片同步显示该开关状态。

升级时保留设备授权、通知订阅和 VAPID 密钥。手机可能仍使用旧 Service Worker：先打开一次获取更新，再关闭该应用及同站点 Safari 页面，从主屏幕重新打开；看到“接收任务提醒”开关后再开启。

关闭任务提醒会取消排队中的提醒，但保留测试通知订阅；关闭全部通知或移除设备会同时关闭任务提醒。已经发出的请求或系统已经显示的提醒不能撤回。

## 原始记录与投递路径

```text
原有 JobExecutor 执行任务 → scheduler.db 保存运行结果
→ DeliveryRouter 遵循原有 silent_on_success / web_log / notifications.enabled
→ notifications.jsonl 保存原始消息与稳定 event_id
→ 手机入口的后台 worker 补扫消息 → push.sqlite3 中的 task_outbox
→ 系统推送服务 → 手机提醒 → 打开项目的任务消息页
```

不新增第二套调度器，不修改 Agent 会话语义，不把推送回执作为原始任务结果。定时任务和通过原有任务入口手动执行的 Job 都遵循相同投递规则。只给已批准、已订阅且单独开启任务提醒的手机投递；开启之前的已有消息与没有事件元数据的旧日志不会被补推。

NotificationCenter 和 JsonNotificationStore 保持原有消息读取接口。新日志增加 event_id、created_at 元数据；轮转时保留已有元数据与时间，避免每次写入都把旧事件变成新事件。旧日志仍可正常读取。相同运行的重复投递沿用 `job-run:<run.id>`，提醒按运行与设备组合去重。

推送正文固定为“电脑有一条新的任务结果。打开交易罗盘查看。”，不包含任务名称、研究内容、会话内容或凭据。点击任务提醒后，由已授权接口读取原始消息；不会接受推送载荷中的任意 URL。

## 点击通知后的定位

仅在用户点击任务通知时，Service Worker 在手机 IndexedDB 保存一条有效期五分钟的定位意图。应用已经打开时通过消息切换到“任务消息”，保留当前会话与未发送草稿；重新打开时使用同一电脑来源下的 `?view=notices`。页面启动和恢复到前台时也会读取该意图，因此不只依赖系统保留启动 URL 或及时转发消息。

页面切换后确认并清除对应意图，旧确认不会删除更新的点击。启动参数也会清除，避免普通刷新重复跳转；仅收到推送不会切换正在使用的页面。意图按应用路径隔离，只保存随机点击 ID 与时间，不含会话或任务正文。旧版本忽略这份手机本地状态，回退无需迁移电脑数据。

## 重试与边界

- worker 只随手机监听入口运行，约每两秒检查。关闭手机访问会停止后续投递；已经进行中的网络请求可能先完成。
- 每次发送先在 SQLite 中登记一次尝试，租约 60 秒。电脑重启后等租约到期再恢复，避免立即重复抢占。
- 暂时网络错误、HTTP 408 / 429 / 5xx 重试：从 30 秒逐步增加，间隔最大一小时；至多 24 次，并限制在消息产生后的 24 小时内。
- 推送服务返回 404 / 410 时停止使用该订阅，手机需重新开启通知。消息到期不删除仍然有效的订阅。
- 使用固定投递 ID、Web Push Topic 和通知 tag 减少重试造成的重复显示。网络发送与本地保存回执无法成为一个事务，不承诺系统通知严格只显示一次。
- 原始通知日志仍沿用项目的保留条数，默认 500 条。补扫仅覆盖尚在该日志中的事件；手机入口关闭期间若日志已轮转移除某条事件，无法再从该日志补建它的推送记录。已进入 SQLite 队列的提醒继续遵循自身重试期限。
- `accepted` 仅表示推送服务接受；`received_at` 表示手机 Service Worker 显示通知后回传，实际锁屏可见仍由真机确认。
- 手机离线时可能收到系统推送而无法回连电脑；当前同源模式的回传不是可靠回执队列。没有回传不代表用户一定没看到。
- 电脑睡眠、关机、离线以及跨网络不可达的限制仍然存在。国内 Android 设备与浏览器需另行验收。

## 验证与恢复

测试覆盖原任务投递开关、订阅单独授权、历史不补推、同运行去重、重启租约、失败重试、关闭/撤销、过期订阅、消息保留及载荷隐私。PWA 浏览器测试通过真实任务结果投递路径与后台 worker 观察推送服务调用；服务商和操作系统投递在自动化测试中仍使用替身。

定位测试执行实际注册的 `notificationclick` 处理函数，使用浏览器已显示的通知、真实消息传递和 IndexedDB，模拟操作系统的窗口激活。覆盖已有页面切换并保留草稿、启动 URL 丢失参数后的定位，以及消费意图后普通刷新不再跳转。自动化测试不能代替 iPhone 锁屏点击验收。

数据库仅增加 `task_preferences` 与 `task_outbox` 表，不迁移或删除已有订阅。部署到独立测试实例前备份移动端 SQLite 状态。回退代码后旧版本忽略新增表和通知元数据；原始任务结果、授权、证书与订阅保持可读。停止测试实例或关闭手机访问可停止自动投递。

独立测试实例继续关闭实际定时任务和第三方渠道；真机验证应运行明确标记的资源自检任务，通过原有 DeliveryRouter 生成消息，不能启动实际交易任务来验证通知。
