# 记忆去重与修订历史

记忆页的「历史」记录可展开查看保留或替代记录的正文、ID、版本和当前状态。
若结果后来再次修订，会分别显示当时的结果和后续版本。查询结果不受页面当前的
有效/候选/历史筛选影响。

置信度反馈、转为候选和归档也保留变化前的版本，并连接到后续版本。重复交付同一
反馈不会重复升版。复盘按已选中的记录 ID 更新并校验内容，完全相同的历史副本不会
阻止有效记录接收反馈；若正文已修订，则拒绝将针对旧正文的反馈应用到新结论。

- **完全重复，已保留一条**：相同内容的副本去重，不表示 AI 重写了正文。
- **经 AI 审查后合并**：相似记忆整理流程生成合并文本，再经模型审查后提交。
- **经 AI 审查后修订**：模型审查通过的替换或纠错，不把多条输入自动等同于同义合并。
- **已更新**：有修订关系，但不据此推断 AI 参与。旧记录来源为 curator 也不足以证明经过 AI 审查。

页面的置信度和访问次数均有明确名称，不表示重复相似度或重复数量。历史条目不显示
「待复评」，也不会单凭残留的复评标记触发有效记忆维护；有效记忆仍可等待复评。

## 存储与兼容

继续使用 `.memory_meta.json` 台账、现有条目 ID 和版本。新增的后继版本、变更类型及
审查方式由后续正常修订写入。已有 `duplicate_of:` 和后继 ID 可直接读取，无需重写
历史或重新合并。记录未保存足够关联、后继版本有歧义或存在循环时，页面明确说明
无法完整追溯，不从文字相似或来源名称猜测结果。
本次改进保留后续操作的完整历史；过去已缺失的版本不会用当前版本补造。

正文、状态、固定记忆保护、3000 字符有效额度和 AI 合并判断规则保持不变。
旧版本可忽略新增元数据继续读取原有内容。回滚前保留完整台账备份，以保存新版本
写入的追溯元数据；回滚代码不会为缺失的旧历史补出审查依据。

## 停服后的重新复评

长期未访问只触发复评，不证明知识失效。服务停摆也不会自动延长或缩短用户规则的
有效期。旧版本曾因时间衰减停用的条目，可在用户要求后按日志核实清单重新开放为
候选；既有证伪、人工停用和重复副本不会因此一并恢复。

`write_knowledge(action=maintain)` 和定时策展均会审查低信任候选，依据完整正文、
当前用户规则、交易制度与已保存的关联观察做 AI 判断。经验性结论需要至少两个
不同会话的独立实战观察；制度原则必须由明确制度或用户规则支持。未访问时间、
重复引用、自述和恢复请求不算验证。流程、工具路由和评分表继续由 Skill 承载。
证据不足保留候选；明确冲突或证伪才停用；通过审查且额度允许才进入有效集合。
采纳或停用提案还需独立 AI 复核，检验是否从个案过度推广、混淆充分条件或违反
记忆与 Skill 的职责；复核未通过保留候选和具体缺陷，供后续复评修订。

模型失败或引用不存在时保留原状态并允许重试；审查过程中记忆版本或用户规则变化，
拒绝用旧上下文提交。新观察可再次触发待定候选的评估。复评保存理由、引用内容快照、
审查时间和前后版本；审查时间不冒充访问时间。3000 字符只计算最终有效正文。
工具回执区分 AI 提案与实际保存结果：因容量或门槛限制留下的仍显示候选，
修订后与已有有效内容一致的显示合并，并保留通往已保留条目的后继关系。

恢复仍使用现有迁移脚本，默认只操作副本预览：

```sh
python scripts/migrate_memory_lifecycle.py --memory-dir /path/to/memory_vault \
  --reopen-stale-evidence /path/to/archive-log-evidence.json
```

清单以条目 ID 为键，包含精确正文和 `stale` 日志的路径、行号及原文。全部匹配后
才开放复评。停止旧写入进程后添加 `--apply --backup-dir /path/outside/vault` 可应用，
并先备份整个记忆目录；重复应用同一清单不会再次恢复已经复评的条目。

「历史」包含旧版本和停用记录，其数量不是失效知识的数量。重新开放或再次修订
仍保留旧版，因此历史数量可能增加。迁移快照中有明确旧哈希和时间的后继关系会
补回；缺失、歧义的关联仍显示无法追溯。
