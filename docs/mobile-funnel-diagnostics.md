# 公网连接故障诊断

目标是区分“手机访问不到电脑”发生在哪一层，并用原授权恢复访问原会话。诊断计数增加、进程存活、配置存在或一次重启成功，都不能独立证明长期稳定。

## 数据路径与诊断位置

手机 HTTPS → 供应商公网接入 → Tailscale 传输 → 入站权限与目标检查 → 本机 Go TLS → 本机 Python HTTPS → 手机授权 → 原会话记录。

连接组件的私有 `status.json` 新增 `diagnostics` 字段。它只记录当前组件进程的状态、固定错误类别、计数和最近八次事件；重启后重新计数。原来的 `instance` 与 `updated_at` 用于识别进程及状态新鲜度。它不是新的业务记录或授权依据，也不是可公开访问的诊断接口。

| 观察 | 含义 | 不能推断 |
| --- | --- | --- |
| `control.status_available` | 能读取嵌入组件本地控制 API | 公网路径可用 |
| `control.online` | 本地状态中的自身在线标记 | 手机一定能访问，或离线标记意味着全部已建立连接失效 |
| `control.funnel_permission` | 当前自身节点具备监听 443 所需的 Funnel 能力 | 某个具体入站中继连接必然获准 |
| `control.serve_config_read` / `funnel_configured` | 能读取内存中的转发配置，且本节点域名的 443 入口已启用 | 控制面、DNS、所有中继均已同步 |
| `control.listener_open` | 本程序仍持有监听器 | 网络或 TLS 握手正常 |
| `control.health_issues` | 上游报告的健康问题数量 | 问题具体内容或严重性；本诊断不保存原始说明 |
| `ingress_permission_denied` | 上游明确拒绝一次入站权限检查 | 需要重新注册账号或扩大用户访问策略 |
| `ingress_config_missing` / `ingress_target_missing` | 上游在处理入站连接时找不到配置或目标 | 磁盘身份文件丢失 |
| `tls_client_hello` | TLS 证书回调收到握手请求 | 所有握手都会经过回调，或握手最终成功 |
| `tls_certificate_failed` / `tls_handshake_failed` | 证书回调失败，或 HTTP 服务器报告 TLS 握手错误 | 手机授权失效 |
| `http_request` | 请求已到达 Go HTTP 处理器 | Python 返回成功、手机已授权或 Agent 执行完成 |

计数差值需要与实际 HTTPS 请求时间对照；公网扫描、手机轮询也会增加计数，不能把每个增量都归因于验收脚本。

## 隐私与生命周期

- `StatusWithoutPeers` 只读取自身状态；诊断不保存其他节点、账号、地址、原始健康说明、模型凭据、Cookie、请求内容或会话内容。
- 上游日志只匹配固定版本源码中的已知类别；不格式化、不保存日志参数。TLS 错误也只计类别，原始错误文字丢弃。没有启用供应商诊断日志上传。
- 记录沿用现有私有目录与原子写入，事件数量有界。没有新增网络监听器、公开路由或本地控制 API 代理。
- 注意：整个 `status.json` 原本还可能包含登录授权链接。只能提取 `diagnostics` 字段用于排查，不能上传或公开整个文件。诊断输出不自动发送到外部服务。
- 读取诊断不改动转发配置、手机授权、电脑身份或会话；本轮没有新增自动重启策略。

## 与上游实现的语义对应

固定版本 [tsnet](https://github.com/tailscale/tailscale/blob/v1.102.4/tsnet/tsnet.go) 的 `ListenFunnel` 配置一个本节点入口；本项目对应的是电脑拥有的移动端入口，不是用户会话、任务或手机身份。

固定版本 [入站处理](https://github.com/tailscale/tailscale/blob/v1.102.4/ipn/ipnlocal/serve.go) 分别检查入站能力、ServeConfig 和目标。这里的固定日志类别用于定位哪一步拒绝，不能将其解释为允许程序修改供应商账号策略。

磁盘存在 `AllowFunnel` 而内存配置不可读、诊断没有拒绝事件但公网仍失败，都是反驳简单“配置丢失”解释的证据。此时应继续检查传输和实际请求，不复制上游问题报告中的重启方法作为根因修复。

## 验收与恢复

先确认无正在执行的回合，记录原授权、会话和节点密钥指纹，再只操作指定测试实例。临时验收设备必须经过正常配对与电脑批准，测试后撤销；凭据只保留在验收进程内存中。

公网读取原会话、原授权恢复、桌面管理路径不公开、撤销立即失效分别验收。组件暂停实验需独立恢复看护，且明确区别于整机睡眠、真实断网和手机网络切换。

更新前保留原 wheel；回退只重装同一实例并保持原运行参数，不覆盖配置、节点或会话目录。不得同时运行两份相同节点状态，不得以清空授权或降低 TLS 检查来恢复访问。实际结果记录在[主验收记录](mobile-managed-access-review.md)。

## 本轮已观察到的路径差异

一次关闭后重开的复现中，本地控制在线且内存转发配置正确，公网 TLS 仍失败超过 75 秒。随后逐个测试域名解析出的四个地址：其中两个能完成 HTTPS，另两个握手失败；数分钟后，在没有再次重启或修改配置的情况下，四个地址都能用同一授权读取原会话。

因此普通域名请求成功一次不能代表所有接入路径已恢复，失败一次也不能证明所有手机都无法访问。逐地址检查只用于保留原域名与 CA 验证的诊断请求，不修改 DNS、不硬编码产品 IP，也不绕过证书校验。具体转发或同步机制的根因仍未确认。

## 程序内的公网检测

电脑开启托管手机连接后，每分钟自动从本机检查一次自己的公网入口；桌面设置显示 `connection.public_check`，与连接生命周期的 `phase` 分开。检测只使用现有匿名 `/mobile/v1/browser/connection` 接口，验证返回的入口地址与电脑身份。它不读取会话、不提交手机凭据、不创建配对，也不新增公网诊断接口。

每轮重新解析当前域名，只连接解析出的公网单播地址，最多八个；混入私网、组播或过多地址时停止该轮检测。DNS 最多等待五秒，各地址并发请求各限八秒，保留原域名的 SNI、Host 与系统 CA 校验，不使用环境代理、不跟随重定向。响应头、响应体读取均有上限，重复的缓存和安全响应头允许存在，重复的长度或传输编码头拒绝解析。

状态包括：检测中、已检测路径均可访问、部分路径未连通、此电脑全部路径未连通、无法完成检测、结果过期。`checked_at` 是本轮开始时间，超过 90 秒或系统时间回拨后不再把它展示为新结果。检查范围始终是此电脑的网络；没有 IPv6 出口、手机使用不同网络或 DNS 等情况都可能使电脑与手机结果不同。通过不证明每台手机可用，失败也不证明手机授权失效。

结果只保留在内存中：监听器就绪后开始检测，所属服务关闭时取消，重启后重新检测。检测失败不关闭监听、不修改节点、配置、会话或已批准设备，不触发自动登录、重启或重新配对。桌面读取状态失败时也不会继续展示缓存的公网成功提示。

验收需同时覆盖真实 TLS 响应、部分失败/全部失败/恢复时原授权读取原历史，以及安装 wheel 后的实际设置页面。测试数据不能代替真实手机网络验收；本功能提高可观察性，没有修复此前尚未定位的 Funnel 间歇故障。
