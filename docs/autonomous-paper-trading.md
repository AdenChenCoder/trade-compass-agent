# 自主模拟交易

## 用户行为

- 持仓页提供一个全局「Agent 自主交易」开关，默认关闭，状态保存在数据目录，重启保留。
- 开启时，对话和既有定时任务中的 Agent 可以基于分析自主决定买卖，不必逐笔确认。
- 关闭时，Agent 仍能执行当前用户明确的交易或同步指令。人工页面录入保持原状。
- 用户 rule 继续优先于 Agent 生成的策略；不额外添加仓位、止损、回撤等投资限制。
- 使用现有账户及流水；不新增收益评价体系或外部通知。
- 开启后，已有调度器每天在上海时间 09:35、10:05、10:35、11:05、13:05、13:35、14:05、14:35
  运行「盘中自主交易」，仅交易日运行。每轮刷新分析，决定执行买卖或持有。
  服务须运行、调度器须开启；休市不补单，同一时段重启不重复触发，错过时段最多补跑 5 分钟。

## 实现与契约

交易路径：AgentLoop 当前用户消息 → ToolRegistry 区分明确指令/自主决策 →
服务端市场取价 → 记账锁内校验开关、市场规则和购买力 → paper_trades.jsonl →
持仓、决策日记、原有会话工具记录。

明确指令由模型理解自然语言，并引用当前用户消息中的原文；服务端验证引用确实来自
当前交互，而非历史记忆、工具结果或定时任务。这不是独立于模型的自然语言语义证明。
没有明确指令引用的交易按自主决策处理。定时任务不具备交互用户指令豁免。
同步工具仅用于用户明确要求的外部交易录入，不能充当自主交易的替代入口。

账户 `capital` 保持已分配总资金的含义。可用资金从该账户现有流水计算：
总资金 − 买入成交额 + 卖出成交额 − 全部交易费用。浮盈不增加可用现金。
人工同步仍可录入，但流水会影响后续模拟买入的购买力；余额不足时拒绝买入，仍可卖出。
现有流水按账户类型归属；若同一类型存在多个账户，不能推断归属或合并资金额度，
返回无法确定购买力的原因，不改写历史账户身份。

模拟交易按服务端有效市场价执行，拒绝过期或无效行情，遵守已有交易日历、交易时段
和标的交易制度。失败返回模型，由它重新获取行情、调整数量、卖出或放弃。
外部同步的已成交价格及人工入口不受模拟行情/购买力校验影响。

开关检查与购买力校验在追加流水的同一临界区内，使用线程锁和跨进程文件锁。
关闭请求返回后不再提交新的自主成交；已经成交的记录保留。既有分析任务保持运行，
新增盘中自主交易任务停止。开启期间每日最多启动 8 轮盘中 Agent，会增加模型调用。
不强制每轮成交；买卖决定必须调用工具，emit_signal 和计划不等于成交。

盘中链路：TickScheduler → autonomous_trading workflow → ScheduledAgentSession →
autonomous-paper-trading Skill → 分析/下单工具 → 既有账户流水。
晨间计划保持研究步骤，盘中 Agent 通过会话/记忆搜索读取并重新验证，不直接机械执行旧信号。
每轮独立会话 ID 带 run_id；任务详情和 workflow artifact 保存结果，会话保存分析与工具回执，
其记录不参与原有 7 天定时会话清理，供跨月观察。超时或停止的盘中回合不能继续提交交易。

## 验收与恢复

- API 更新开关后，新建服务对象、现有 Agent 和定时任务读取一致的状态。
- 关闭拒绝自主交易但保留明确指令与人工同步；旧用户指令不能授权下一轮。
- 买入含费用不得透支；连续/并发交易、卖出回款、人工同步均反映在余额中。
- 行情过期、非交易时段、T+1 和资金不足的失败进入原有工具交互记录；不写成交流水。
- 失败后模型可以重新决策并成功成交；UI 与工具展示同一账户可用资金。
- 源码和安装包使用同一实现，数据只写入配置的数据目录。
- 验证盘中触发、拒单后调整成交、同槽重启去重、关闭/午休/休市跳过和跨月记录保留。

不迁移或重写既有流水。关闭开关即可恢复仅按明确指令操作的模式；回滚代码保留
账户与交易文件，新开关文件可由旧版本忽略。
