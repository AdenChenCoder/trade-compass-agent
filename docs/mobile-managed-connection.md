# 在手机上连接交易罗盘

当前开发分支已提供项目内的手机连接入口，尚未发布到 PyPI。手机使用项目自带的 PWA，页面、Agent、会话历史和任务结果均由你的电脑提供。

## 连接步骤

1. 启动电脑上的交易罗盘，进入 **设置 → 连接手机**，点击 **开启手机连接**。
2. 首次使用时，点击页面中的 **登录 / 注册**，在 Tailscale 页面完成账号登录；如提示 HTTPS / Funnel 权限，点击 **继续授权**。回到交易罗盘后，程序会自动继续准备连接。
3. 出现 **手机连接已开启** 后，点击 **生成配对二维码**。手机相机扫码，名称默认为 **我的手机**，点击 **连接这台电脑**。想从主屏幕使用，可先按手机页面提示添加，再打开应用连接。
4. 电脑会显示这台手机专属的六位配对码。在手机输入这六位数字，输入完整后自动验证并进入会话，无需再回电脑点击批准。配对码五分钟内有效，连续输错五次需重新扫码。

若主屏幕应用未带入配对信息，展开电脑上的 **连接遇到问题？**，选择 **复制配对链接**，在手机 **扫码或安装遇到问题？** 中粘贴。二维码过期后可重新生成。已配对手机无需重复扫码；新增手机时点击 **连接另一台**。

电脑侧的公网检测也收在 **连接遇到问题？** 内。检测只反映该电脑当时的访问路径，不清除手机授权或自动重启连接。

需要任务通知时，在手机应用的 **连接** 页面开启通知和 **接收任务提醒**。系统通知只包含通用提醒；点击后通过授权连接读取电脑上的任务消息。

安装本项目的 wheel 后，无需另装 Tailscale 客户端，也无需填写域名、证书、端口或账号 Token。账号登录及系统通知授权仍需本人完成。国内外 Android 的浏览器与系统推送能力不同，目前尚未完成全部真机覆盖。

## 手机界面更新

已安装到主屏幕的应用会保留离线页面。全新打开页面时会检查更新，新版完整下载后自动加载；使用过程中或从后台返回时发现新版本，会显示「检测到新的版本，是否更新？」，点击 **确定** 后更新，当前会话位置、草稿和配对保留。离线时仍可打开已缓存的页面。

较早的版本没有更新入口。首次迁移时，让主屏幕应用联网打开几秒，再从手机多任务界面彻底关闭并重新打开。无需卸载应用、清除网站数据或重新配对。新版「连接」页会显示 **我的连接** 和 **通知与提醒**。

## 日常使用与恢复

- 电脑保持开机、联网并运行交易罗盘时，手机可以同步。电脑睡眠、关机或离线时不能继续执行新任务或提供新的结果。
- **关闭连接** 会停止公网手机入口；电脑工作台仍可使用，原会话、手机批准状态和通知偏好保留。再次开启会复用本机保存的供应商身份。
- 手机短暂断网或入口暂时不可用时，恢复联网后会继续尝试同步，原会话和草稿保留。若电脑端提示连接组件已退出，则按提示检查网络并点击 **重新连接**。不要删除连接状态目录来尝试修复，否则可能丢失原域名对应的节点身份。
- 在电脑 **已配对的手机** 中 **移除** 并确认后，该手机后续访问立即失效。关闭入口不等于撤销供应商账号中的设备或权限。
- 同一台电脑的更新和正常重启应保留原入口；供应商删除节点、撤销权限或改变域名时，不能保证原入口继续有效。程序不会把地址变化悄悄当成成功重连。

## 数据与连接服务

跨网转发使用 Tailscale Funnel。它是外部基础设施，项目不运营业务云中心。正常转发路径中，手机的 HTTPS 在用户电脑终止；公网只开放移动端路径，桌面配置与管理 API 不对外提供。

经批准的手机可以读取会话并发起 Agent 对话，沿用电脑端的业务确认规则。供应商仍可看到账号、节点、连接时间、地址和流量等元数据；还需要信任浏览器、终端、域名与证书体系以及软件分发。不能把这套 PWA 描述为抵御恶意域名供应商的独立签名客户端。

Funnel 的服务限制、长期可用性与适用套餐仍需在发布前复核。本次验证没有购买服务，也没有验证所有使用场景永久免费。当前验收及限制见 [安全审查与验证记录](mobile-managed-access-review.md)。

## 开发、分发与状态位置

Python wheel 内含项目 Web UI、移动端 PWA 和 macOS / Linux 的 ARM64、x64 连接组件。构建时固定 Go 工具链和依赖，分发依赖许可证；运行时检查包内 SHA-256 清单，校验通过后释放到可写数据目录。此校验用于检测损坏或清单不匹配，不替代对安装包来源的信任。

源码开发首次使用该入口前，在仓库根目录准备前端和连接组件：

```sh
pnpm install --frozen-lockfile
pnpm --dir apps/web build
pnpm --dir apps/mobile build
python scripts/build_mobile_helper.py
```

构建组件需要可用的 Go 启动器及 Go 1.27.1 工具链；可通过 `TRADE_COMPASS_GO` 指定启动器的绝对路径。构建阶段可能下载工具链和依赖。`uv build` 自动执行相同的组件构建 / 清单检查；安装已有 wheel 和正常运行不需要 Go，也不在运行时下载连接程序。

构建会从固定模块读取 Tailscale 版本，并写入包含本项目组件源码摘要的构建标识，例如 `1.102.4-compass.<摘要>`。组件的离线 `--version` 返回该标识；安装包冒烟将它与包内清单核对，拒绝缺失或不匹配的版本信息。

| 内容 | 位置与生命周期 |
| --- | --- |
| 已安装页面、压缩组件、校验清单、许可证 | Python 包内，只读 |
| 已校验的可执行组件 | 配置的 `data_dir/mobile/bin/<SHA-256>/` |
| 供应商节点身份、证书及连接状态 | `data_dir/mobile/funnel/`，私有可写目录 |
| 手机身份、批准状态、任务推送记录 | 原有 `data_dir/mobile/` 下的持久记录 |
| 会话与任务结果 | 原业务记录，连接重启不会重建或替换 |

主程序创建连接子进程并持有父子通信管道；关闭手机入口或主程序退出时停止连接。父进程意外退出、管道关闭时，子进程也退出。源码开发与安装包采用同一个控制器和业务接口。

新配置默认使用 `mobile.provider: tailscale`，但默认不打开连接。原配置没有 `mobile` 段或该段为空时，首次保存开关也会保存默认 provider，确保重启后沿用同一连接方式。已有非空 `mobile` 配置未指定 provider 时，继续按旧的手动配置解释，避免升级时意外注册新节点或改变已有地址。此前独立探针的节点迁移是开发维护操作：先停旧进程并备份配置和完整状态，再迁入本机数据目录；不能同时启动两份相同节点身份。普通新用户只需完成上面的界面步骤。

当前已在 macOS ARM64 执行包内组件，并在仓库外的只读安装目录完成移动端检查；其余三个目标已交叉构建，尚未逐平台运行。项目内全新账号的完整真机首次流程、供应商真实证书续期、长时间断网恢复和国内外网络持续运行仍待验收。
