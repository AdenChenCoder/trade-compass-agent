# 托管手机接入：安全审查与验证记录

更新日期：2026-09-14（北京时间）。当前阶段：项目内授权界面、连接生命周期和安装包集成已落地，并在独立测试实例完成实际启停验收；尚未发布，也未宣布长期稳定性通过。使用入口见 [手机连接](mobile-managed-connection.md)。

## 用户目标与范围

用户在项目内开启手机访问，首次完成供应商授权并扫码批准，手机安装项目自带 PWA。
不同网络下使用同一个 Agent、原始会话和任务结果，重启后保持安装入口和设备身份。
安全优先于稳定、易用与免费；账号注册只作为必要的首次步骤。付费尚未获准采用。

本轮排除：局域网 / 公网 IP 直连、自动端口映射、自带服务器、自部署中继和项目自营节点。
历史开发实现保留用于回归，不作为正式交付候选，不删除用户的既有配对和会话。

观察到的缺口是缺少已验证的安全跨网入口。候选实现机制是供应商托管的 TLS 转发。
仅“监听启动”或“页面能打开”不是最终用户结果；固定来源、身份验证、停止 / 恢复与真实手机体验均须通过。

## 安全边界

1. 优先要求正常数据路径中，TLS 在用户电脑终止，公网中继无法读取会话正文、设备凭据和操作内容。
2. 仍信任终端、浏览器、域名 / CA 体系、供应商控制面及分发的软件。不能宣称抵御恶意供应商控制域名后向浏览器替换应用代码；普通 PWA 没有原生应用那样的独立签名分发信任根。
3. 供应商可以看到账号、节点、连接时间、地址、流量等元数据。私钥应在电脑生成和保存，禁止开源包共享私钥。
4. 公网只提供移动端白名单入口。桌面配置、模型凭据、任意文件和管理 API 不得透过代理访问。
5. 电脑批准设备后才可读取会话或发消息；撤销后拒绝后续访问。移动端使用同一个 Agent，意味着已授权手机也拥有相应的 Agent 操作能力，不能把接口数量少说成“只有只读权限”。沿用既有业务确认语义，不另建一套交易 / 工具权限规则。
6. 重试只能补取结果，不能自动重放 Agent 工具操作。通知仅带通用提醒，完整结果仍由授权接口返回。
7. 固定文字的蜂窝网络验证已由用户确认。后续只将既有独立测试实例的移动端接口接入公网，正式业务服务保持现状；测试实例中的原会话仍受设备批准控制。

## 当前项目的端到端映射

会话路径：手机 Cookie / 请求 → 移动端 HTTPS 与来源检查 → DeviceStore 批准状态 → MobileTurns 持久请求记录 → 共享 execute_agent_turn / 会话执行锁 → 原 SessionStore → 电脑和手机读取同一历史。

任务路径：电脑任务完成 → 原始通知记录 → 可重建待推送状态 → 系统 Web Push → 手机点击 → 授权读取原始任务消息。

恢复路径：设备凭据哈希和请求记录保存在电脑可写数据目录；未知执行状态不重放。连接组件的节点状态与原始会话分离，连接失败不能删除用户历史。

现有安全回归覆盖配对批准、过期 / 单次邀请、撤销、实际 TLS、来源 / CSRF、桌面路由隔离、同一历史、请求去重和不确定执行状态恢复。它们不证明外部中继可用。

接入约束及当前落实：

- `mobile/tls.py` 默认继续要求公开端口等于本地监听端口。新增显式 `mobile.tls_relay` 开发配置仅在 loopback 监听、完整证书配置及公开 HTTPS 443 时允许不同的本机端口；域名、有效期和私钥匹配仍校验。
- `mobile/api.py` 要求实际 HTTPS，`mobile/server.py` 禁用代理头信任。不得为接入代理而全局信任 `X-Forwarded-Proto` 或关闭来源 / 证书检查。
- Go 组件终止外部 TLS 后，仅向配置中的 loopback IP HTTPS 移动端监听器转发，使用系统 CA 和公开域名校验证书。两跳均为实际 TLS；不使用环境 HTTP 代理，不信任客户端转发头，不代理桌面端口。
- 首次切换到新的公网 origin，需要通过正常流程在新来源配对 / 安装。不能跨来源复制旧 Cookie，也不能将入口变化误报成会话丢失。
- 源码与 wheel 共用连接控制器。包内含四平台组件、依赖许可证和 SHA-256 清单；运行时只向可写数据目录释放经过校验的组件，不下载程序。macOS ARM64 的只读安装目录已验证；其他目标的运行与完整升级回退仍待验收。

## 隔离组件

[scripts/mobile-funnel-probe](../scripts/mobile-funnel-probe/README.md) 固定使用 tsnet v1.102.4。
默认只准备本地状态；显式连接时才接触供应商。默认公网仅有固定测试文字与 `/healthz`；显式开发桥接配置下仅开放 `/mobile` 和兼容的 `/phone` 移动端路径，根地址跳转到项目 PWA。
拒绝继承其他任务的 TS 身份配置，随机匿名节点名，独立私有状态，关闭自动端口映射和诊断日志上传。
只接受供应商白名单 HTTPS 授权链接；固定来源变化、权限异常和状态异常均不能继续宣称已连接。

源码发现：`ListenFunnel` 只检查能力，不自动完成首次启用；官方 CLI 另走 `QueryFeature("funnel")`。
探针跟随这一语义，在缺少 HTTPS / Funnel 能力时提供供应商操作入口；不自动修改 tailnet 的访问策略。
该交互是否对全新账号开放且足够简单，必须实际登录验证。

### 2026-09-13 首次公网检查

授权后首先出现 TLS 握手超时，且未观察到域名证书文件。之后暂停探针，以同一节点身份执行一次证书诊断，成功取得证书；恢复探针后公网访问通过。
保留这一首次失败，不将随后成功归因于已证实的单一原因：尚不能区分首次签发、传播耗时和请求超时设置各自的影响。
正式集成需要明确的证书准备状态和有界错误诊断，不能把 `ListenFunnel` 成功当作可以安装 PWA。

本轮客户端分别使用显式不经过 HTTP 代理的 curl / Python HTTPSConnection，以及使用现有系统代理设置的 urllib；两者均成功。
没有修改 Mac 的系统网络或代理设置，因此不能据此证明电脑底层网络没有 VPN / 透明代理，也不代表国内其他运营商可用。
当前证书有效期至 2026-12-11，自动续期尚未实测；持久化证书不能替代续期验收。

原始检查结果保存在仓库外测试目录的 `public-access-before-restart.json` 与 `public-access-after-restart.json`，不包含业务数据或私钥。
